## 产品决策

### P-001 物种原型：黑毛蚁 *Lasius niger*
- **状态**：已采纳（2026-10-21）
- **备选**：切叶蚁（真菌农场、分 4 级体型，分工最丰富，但工作量多约 30%）、收获蚁、不指定物种
- **决定**：黑毛蚁。经典的土栖蚁，研究资料最多，会放牧蚜虫，蚁穴是“小土丘 + 地下多层房间”的结构
- **后果**：工蚁体型基本一致，**没有兵蚁职别**；守卫和防御是工蚁承担的一项任务。工蚁体长取 3–5 mm 的轻微变化（代码中 `size` 为 0.86–1.08）

### P-002 美术风格：风格化低多边形，全部程序生成
- **状态**：已采纳
- **后果**：不需要外部模型和贴图；所有几何都在代码里生成，颜色主要来自顶点色和实例颜色

### P-003 蚁穴呈现：真 3D 地下隧道网络
- **状态**：已采纳
- **备选**：2.5D 蚂蚁工坊式玻璃夹层剖面（更清晰、更省事）、两者都做
- **决定**：真 3D。土壤可以半透明，相机能飞进地下观察
- **后果**：需要一套“从任意角度都能看进空腔”的渲染方案，见 T-010

### P-004 蚁穴生成：预设程序化生成，之后按人口扩建
- **状态**：已采纳；第二阶段实现了扩建（见 T-020）
- **备选**：蚂蚁实时一粒一粒挖掘，蚁穴完全动态生长（难度和性能开销都大）
- **后果**：第一阶段的挖掘只体现在地表土粒上，隧道几何不变；扩建放在第二阶段

### P-005 规模：1000–3000 只
- **状态**：已采纳。第一阶段初始 1000 只，上限 3000（`CONFIG.colony.maxPopulation`）

### P-006 玩家角色：观察 + 轻度干预
- **状态**：已采纳；干预工具放在第三阶段
- **内容**：投放食物、放置障碍、引入天敌、浇水

### P-007 生态要素范围
- **状态**：已采纳

- **不做**：敌对蚁群与领地战争、季节与婚飞

### P-008 交付节奏：原型先行，分阶段迭代
- **状态**：已采纳。三个阶段的内容见 ROADMAP.md

- **状态**：已采纳（2026-10-21，第一阶段验收时）

## 技术决策

### T-001 技术栈：Three.js r170 + TypeScript + Vite，界面用原生 DOM
- **理由**：界面只有几个信息面板，引入 UI 框架不划算；面板每 0.25 秒用模板字符串整体刷新，按钮通过 `data-a` 属性做事件委托

### T-002 尺度：1 世界单位 ≈ 1 厘米，蚂蚁放大到体长 1 单位
- **背景**：真实工蚁只有 3–5 mm，按真实比例在 240 cm 见方的场景里看不见
- **决定**：环境（草高 4–10 cm、房间、深度）按真实厘米尺度，蚂蚁放大约 2.5 倍
- **后果**：信息面板里显示的体长换算回真实毫米（工蚁 `size×4 mm`，蚁后 `size×9 mm`）；房间宽 12–24 cm，最深的越冬室深约 77 cm，与真实黑毛蚁巢的量级相符

### T-003 时间尺度：1 游戏日 = 600 模拟秒，发育期和寿命按比例压缩
- **决定**：1 倍速下 10 分钟过一天，蚂蚁的移动速度接近真实；卵 2 天、幼虫 3.2 天、蛹 2.4 天（约为真实的 1/3）；工蚁寿命 45–90 天（真实约 1 年）
- **模拟步长**：固定 1/30 秒，每帧最多 24 步。20 倍速、60 FPS 下每帧约 10 步

### T-004 模拟层与渲染层分离
- **决定**：`World` 持有全部模拟状态，可以在 Node 中无界面运行（`scripts/simtest.ts`）
- **例外**：地形、植被、食物源在构造时就会创建 Three.js 网格。这些只是几何对象，不需要 WebGL，所以 Node 中也能运行
- **后果**：调参时可以快速做无界面回归测试；第三阶段把模拟移到 Web Worker 时，需要先把这几处网格构建挪出模拟层

### T-005 行为模型：生成器协程 + 运动指令两层
- **背景**：要让成千上万只蚂蚁执行多步骤任务（取卵→搬运→放下→整理），而每一步都需要持续若干帧的移动
- **决定**：
  - **行为层**（`sim/routines.ts`）：每项任务是一个生成器函数，通过 `yield` 下达指令，例如 `goto`、`room`、`exit`、`enter`、`search`、`walk`、`patrol`、`wait`
  - **运动层**（`sim/ant.ts`）：每帧执行当前指令，指令完成后才恢复协程
  - 协程结束后，`Colony.newRoutine` 按分工重新选择下一项任务
- **理由**：任务逻辑可以按顺序书写、容易阅读；协程只在指令完成时才被唤醒，开销很小
- **后果**：任务被打断时（例如死亡）调用 `Ant.abort()`；协程恢复后必须重新检查物品是否还有效（`stillMine`），因为世界状态可能已经变了

### T-006 巢内导航：节点图 + Floyd 全源最短路
- **决定**：蚁穴是由入口、分岔点、房间门、盲端组成的节点图，边是隧道（带采样点的曲线）。节点约 22 个，开局一次性算出所有节点对之间的下一跳
- **细节**：蚂蚁贴着隧道底部行走，并按 `lane` 靠右偏移，对向的蚂蚁自然分道；房间内部在地板椭圆上自由走动；位置做指数平滑，避免切换隧道时跳变

### T-007 地表导航：路径整合返巢 + 信息素招募 + 地点记忆
- **依据**：黑毛蚁的真实觅食方式
- **出巢搜索**：
  - 先去记忆中上次找到食物的地点（觅食地点忠诚性）
  - 否则用左、中、右三个点采样路径信息素，偏向远离蚁穴的一侧
  - 都没有就做相关随机游走
  - 7 cm 内能嗅到食物
  - 侦察蚁对信息素的跟随度只有 25%
- **返巢**：路径整合，直接朝巢口走，带随距离减小的方向误差。只有携带食物时才沿途释放信息素，强度随食物源剩余量增加
- **后果**：路径信息素自然形成从巢口到食物源的放射状路径；食物源搬空后路径会挥发消失

### T-008 信息素：单一路径信息素网格
- **状态**：已被 T-022 扩展（新增足迹通道）
- **决定**：240×240 网格（1 cm 一格），半衰期 90 秒，每 0.5 秒统一挥发一次
- **后续**：警报信息素（第三阶段）作为同一网格类的另一个通道加入

### T-009 蚂蚁渲染：实例化网格 + 着色器步态
- **决定**：工蚁和蚁后各用一个实例化网格，一次绘制完。腿部顶点带 `aLeg`（三脚架分组）和 `aHip`（髋关节支点）属性，每个实例的 `aGait` 由行进距离累加，在顶点着色器里绕髋关节摆动腿部；触角也有轻微摆动
- **后果**：阴影里的腿是静止姿态（阴影用的深度材质没有注入这段着色器），可以接受

### T-010 蚁穴空腔用背面渲染
- **决定**：房间、隧道、土壤剖面墙都只渲染背面（`BackSide`）。离相机近的一侧墙自动被剔除，所以从任意角度都能看进空腔，不需要切割平面
- **透视模式**：地表材质改为 16% 透明、不写深度，隐藏草丛和落叶，开启一盏跟随相机的观察灯；相机进入地下或跟随的蚂蚁在巢内时自动开启
- **后果**：拾取房间时射线命中的是远侧内壁，用于选中房间刚好合适

### T-011 拾取：蚂蚁用屏幕空间，其他对象用射线
- **背景**：蚂蚁很小，射线很难点中
- **决定**：蚂蚁按投影到屏幕后的最近距离选取（16 像素容差，距离相机越近越优先）；房间、食物、入口、垃圾堆、石块、植物用射线拾取，地表模式下地形会遮挡射线

### T-012 物品系统：位置状态 + 认领
- **决定**：卵、幼虫、蛹、食物、垃圾、土粒、尸体统一用 `Item` 表示：
  - `place` 记录物品在哪里：房间、隧道节点、地表、垃圾堆、蚁丘、被携带、已销毁
  - `claimedBy` 防止多只蚂蚁去取同一件物品
- **后果**：任何“取东西”的任务都要先认领、到达后再确认；放弃任务时必须释放认领

### T-013 经济平衡依靠负反馈
- **背景**：调参中先后出现过饿死崩溃和食物无限堆积（见 BALANCE.md）
- **决定**：
  - 储备越多，觅食蚁越倾向于留在巢内（真实蚁群也会这样调节觅食量）
  - 储存的食物会变质：猎物和种子变成垃圾，甜液干涸
  - 进食失败后冷却一段时间，避免死循环
- **后果**：系统自稳定。以后增加新的食物来源或消耗时，要在 `simtest` 里确认储备不会单向漂移

### T-014 验证方式：无界面模拟 + 无头浏览器截图
- **决定**：
  - 行为和平衡用 `scripts/simtest.ts` 验证
  - 画面用无头 Chrome 截图验证，配合 `scripts/extract-shots.mjs` 从捕获结果中提取图片
- **限制**：浏览器自动化工具不支持鼠标拖拽，鼠标交互需要人工测试

### T-015 URL 参数
- **决定**：提供 `?cam=`、`?select=`、`&follow=1`、`&fly=1`、`?hour=` 五个参数（用法见 README），既方便分享观察视角，也用于截图验证
- **第二阶段补充**：`?skip=秒数`（开局在后台快进模拟，上限 20000 秒）、`?view=xray,pheromone,roles,stats`（开局打开显示开关）、`?select=plant:N`。`hour` 改为“快进到下一个该时刻”，可以和 `skip` 一起用

### T-023 发布形态：单个 HTML 文件，双击即可运行
- **状态**：已采纳（2026-10-21，需求方希望不需要服务器）
- **背景**：浏览器禁止从 `file://` 加载外部的 `<script type="module" src>`，普通 Vite 产物必须通过 HTTP 服务器打开
- **决定**：`vite.config.ts` 里的 `singleFile` 插件在打包后把 JS 和 CSS 内联进 `index.html`，并删除原来的分块文件；关闭 modulepreload 和 CSS 拆分，动态导入全部内联。没有引入第三方插件
- **发布文件**：构建时同时写一份到项目根目录 `赛博养蚂蚁.html` 并提交进仓库，方便直接下载双击。用不同的名字是为了和根目录的源码模板 `index.html` 区分
- **前提**：项目没有任何外部素材（P-002），所以单文件就是全部内容。以后如果加入图片、音频等文件，需要转成 data URL 内联，或者放弃这种形态
- **后果**：开发时仍然用 `npm run dev`；第三阶段如果把模拟移到 Web Worker，Worker 也要用 Blob URL 内联创建，不能用独立文件

### T-016 分工模型：行为年龄排序 + 按需目标
- **背景**：第一阶段新羽化的工蚁全部是保育蚁，分工比例会漂移（真实蚁群是年龄多型性 + 按需弹性调整）
- **决定**：
  - 每只工蚁有“行为年龄” = 日龄 + 个体随机偏移（标准差 `polyethism.ageJitterDays`），代表发育快慢的个体差异
  - 每 `reviewDays` 计算一次目标：保育蚁随幼体数增加；觅食蚁比例随“储备够吃几天”在 58%–40% 间变化；剩下是内务蚁（至少 14%）
  - 工蚁按行为年龄从小到大依次对应保育→内务→觅食。正向转换按需发生；逆向转换（例如觅食蚁回巢当保育蚁）只在缺口超过 15% 时发生
  - 每次评估最多转换 `maxShift`（2%）的工蚁；转换记为 `nextRole`，等当前任务结束后才生效
- **后果**：分工比例自稳定，实际人数紧跟目标；觅食蚁大量死亡时会出现“较年轻的工蚁提前转为觅食蚁”事件。信息面板显示“即将转为 X”

### T-017 社会胃：液体食物只存在于嗉囊
- **背景**：真实黑毛蚁不在房间里储存液体，甜液在工蚁的嗉囊里，通过交哺在群体内流动
- **决定**：
  - 每只工蚁有 `crop`（0–1）。储食室只放固体（猎物碎块、种子）；“社会胃”是所有嗉囊之和，只用于显示和决策，不单独存储
  - 饥饿的蚂蚁先喝自己嗉囊里的，再向同房间嗉囊较满的同伴乞食（交哺时两只都停下面对面）；保育蚁在喂幼虫前也会先乞食
  - 归巢的觅食蚁在入口附近房间把蜜露分给多只同伴（`unloadCrop`）；嗉囊满的内务蚁会把甜液分给其他房间（`distributeCrop`）
- **后果**：甜液不会变质（第一阶段的“甜液 4 天干涸”规则随之取消），但总量受嗉囊容量限制，起到自然上限的作用。储备 `reserve` = 固体 + 社会胃

### T-018 接触检测：每帧重建的均匀空间哈希
- **决定**：`SpatialHash` 格子 2 cm、8192 个桶，每个模拟步用链表重建（O(n)）。每只蚂蚁每 8 步检测一次 0.9 cm 内的同伴，接触成功后双方停顿 0.6–1.3 秒、互相转向，冷却 6–16 秒
- **用途**：触角接触统计；满载归来（正在释放路径信息素）的觅食蚁会“激发”巢内的觅食蚁，被激发者 90 秒内更倾向出巢（夜间留巢、饱食抑制都会减弱）
- **后果**：加入接触检测后，1000 只时每步总耗时仍在 0.35 ms 左右。第三阶段的碰撞、天敌感知可以复用同一个哈希

### T-019 向阳育幼室与蛹的温度调节
- **背景**：黑毛蚁常在石块下筑巢，白天把蛹搬到被晒热的石块下方加速发育
- **决定**：大石块下方新增浅层房间（深约 7 cm）。石块加温 = `stoneHeat × max(0, sin(正午相位)) × (1 − 深度 / stoneHeatDepth)`。每 0.01 天比较蛹室和向阳育幼室，评分以 30°C 为最佳，差距超过 1.2°C 才切换（防抖），切换后把所有蛹标记为待搬运
- **后果**：蛹的发育速度随温度变化（系数 0.6–1.3）；面板与事件中能看到“升温到 X°C，保育蚁开始把蛹搬上来”

### T-020 扩建：隧道工作面 + 渐进生长的房间
- **决定**：
  - 占用率 = (成虫 + 幼体) / Σ(rx·rz·`capacityPerArea`)。超过 `trigger` 时规划一间新房间（幼体多则是幼虫室，否则是休息室），在深于 8 cm 的分岔点附近随机找不与现有结构重叠的位置
  - 先挖隧道：工作面 `DigFace` 的边是规划路径截断后的一段，末端节点随挖掘前进，每挖 1 粒土延长 0.25 cm，并重算寻路
  - 隧道挖到后变成新房间的门，房间以 `ready = false` 加入，`grow` 从 0.08 涨到 1；未完工的房间不参与“按类型找房间”和定位
  - 最多 18 只内务蚁同时在一个项目上挖掘；每次挖出的土粒照常运到地表蚁丘
- **后果**：`Nest.rev` / `edge.rev` 递增时视图重建对应网格；土壤剖面墙按新的包围盒重建。房间生长时网格从门口位置缩放展开

### T-021 蚜虫：附着在植物上的种群，带放牧忠诚性
- **决定**：
  - 蚜虫群附着在植物茎秆的一段高度上，Logistic 增长：被照料（90 秒内有蚂蚁来过）时增长率 0.35/天，否则 0.1/天并有 0.08/天的损失；蜜露按数量累积到上限
  - 觅食蚁在搜索中发现有蜜露的蚜虫群就爬上茎秆，采集到嗉囊里，返巢时释放信息素；采过的蚂蚁会以 80% 概率回到同一群（放牧忠诚性）；没有蜜露时会停在上面“守护”25–45 秒
  - 蚜虫数量变化时才重写实例矩阵
- **后果**：蜜露成为社会胃的主要来源；第三阶段的瓢虫可以直接攻击这些蚜虫群

### T-022 信息素第二通道：领地足迹
- **决定**：所有在地表的工蚁每秒沉积 `depositHome`，半衰期 900 秒（路径信息素的 10 倍）。侦察蚁前方足迹浓度大于 0.3 时转向足迹最少的方向，从而倾向探索新区域
- **热力图**：足迹为蓝色底层，路径信息素按浓度从橙红到亮黄叠在上面（标准的 over 合成）；纹理标记为 sRGB、关闭色调映射，避免颜色发白；开启时右下角显示图例

### T-024 玩家干预：World 方法 + 试运行
- **决定**：所有干预都是 `World` 上的方法，返回 `{ok, msg}`；传 `dry` 时只检查不执行。界面的预览圈直接用试运行结果变色，提示文字和真正放置时的拒绝理由完全一致
- **原因**：模拟层保持不依赖 DOM（之后存档、Web Worker 也只需要序列化这些调用）；检查逻辑只有一份
- **限制**：不能堵住入口（入口 4 cm 内不能放）、不能超出活动范围、不能和石块 / 植物 / 水洼 / 食物重叠；只能移除玩家自己放的障碍物
- **地面点**：鼠标下的地面点沿视线对解析高度场 `heightAt` 步进再二分，不对地形网格做射线检测（网格很大，而且草会挡住射线）

### T-025 水洼是“软”障碍物
- **决定**：水洼登记在避障网格里，但蚂蚁移动时不把它当成硬障碍：先沿边绕行，4 秒内绕不开就蹚水通过，速度降到 35%
- **原因**：硬障碍的水洼会永久挡住入口或食物（`walk` 指令没有超时），而真实的蚂蚁遇到浅水也会涉水。水洼会冲刷信息素、随温度蒸发收缩，几分钟后蚂蚁重新铺出路径

### T-027 存档：只存会变化的状态，读档通过重新载入页面完成
- **存什么**：地形、植被、初始蚁穴、蚜虫群的位置都由世界种子决定，不写进存档；写进存档的是蚁穴结构（扩建后会变）、全部蚂蚁和物品、食物源、蚜虫群状态、两个信息素通道（量化为 8 位后 base64）、玩家放的障碍物和水洼、相机视角。存档带版本号和种子，不匹配时放弃读取并开始新的蚁群
- **行为协程不保存**：生成器无法序列化。读档后每只蚂蚁的任务从头开始；走在隧道中途的放到最近的节点，爬在植物上的放回地面，正在搬运的物品直接送到目的地（幼体、食物、垃圾进对应房间，尸体到垃圾堆，土粒丢弃），认领关系全部清空。代价是读档瞬间储食室会多出几十份“在路上”的食物
- **读档 = 重新载入页面**：存档在页面启动时、创建任何视图之前套到刚生成的世界上，视图按读档后的结构从头建立，不需要处理运行中替换蚁穴网格、实例数量等问题。“读取上次存档”和“重新开始”都是重新载入，载入前禁止自动保存以免覆盖
- **存储**：`localStorage`，同步写入，关闭页面（`pagehide`）时也能可靠保存。1000 只蚂蚁时约 1 MB，蚁群长到 3000 只时预计 2–2.5 MB，在浏览器约 5 MB 的配额以内；写入失败时提示玩家。没有用压缩（`CompressionStream` 是异步的，关闭页面时来不及完成）
- **存档代码的位置**：各子系统自己实现 `toSave` / `restore`（需要访问私有字段），`world/save.ts` 负责组装和版本检查，`ui/saveSlot.ts` 负责读写 `localStorage`，模拟层不接触浏览器 API

### T-028 天敌：狼蛛与蚁狮，取代随机的地表意外死亡
- **决定**：去掉“地表蚂蚁每天 3% 意外死亡”，改为两种看得见的天敌，统一放在 `world/predators.ts`（`PredatorManager`），捕食通过 `Colony.kill(ant, cause, false)` 结算，计入 `stats.preyed`
  - **狼蛛**：从觅食范围边缘游荡进来（每天约 1.2 只，同时最多 2 只自然狼蛛），走向范围内随机的目标点，并顺着足迹信息素浓的一侧转向（足迹反映地面上蚂蚁来往的多少，相当于感知振动）。7 cm 内发现蚂蚁就冲刺扑击，60% 成功；进食 90 秒后留下空壳。停留 0.4–0.8 天或吃够 3 只后离开
  - **蚁狮**：开局在距巢 18–75 cm、草少的裸地上有 3 个陷阱。陷阱是一块“松沙”区域：蚂蚁在里面速度降到 40%，同时被拉向中心，越靠中心越陡；进坑 0.6 秒后蚂蚁会转身往外爬。滑到中心就被抓住，进食 4 分钟后把空壳甩出坑外。进食期间不扬沙，坑壁拉力降到 35%，后来的蚂蚁都能爬出去
- **原因**：随机死亡玩家看不见、也没法应对；天敌能被观察、被放入和赶走，第四项“警报信息素与防御”也需要一个具体的攻击者
- **空壳**：作为普通尸体物品留在地表，内务蚁会把它搬去垃圾堆，不需要新的物品类型
- **陷阱的高度**：地形网格建好后不再改动，陷阱做成中心贴地、四周堆起的沙环，靠颜色由浅到深表现漏斗；地表蚂蚁的高度会加上沙面抬高量（`PredatorManager.liftAt`）
- **存档**：天敌位置和状态写进存档的可选字段 `predators`；旧存档没有这一项时沿用新世界自然生成的蚁狮，不需要升级版本号
- **数值结果**：5 个游戏日约 30 只被捕食（其中蚁狮约 60%），与原来的意外死亡量级相当，蚁群照常增长

### T-026 沿边绕行带方向记忆
- **决定**：地表避障从“碰到就沿切线滑开”改为沿边绕行（`Ant.skirt`）：选定绕行方向后保持 1.5 秒；连续 3 秒没走出 3 cm 就换另一边
- **原因**：玩家放的长树枝和自然石块会围出凹角，原来的做法每一步都按当前朝向重新选边，蚂蚁会在凹角里来回摆动、长时间卡住。测试中树枝的一端离侧入口 5 cm、旁边还有一块小石头，修正前最多 9 只同时卡住，修正后最多 3 只，且都会在几秒内脱困
