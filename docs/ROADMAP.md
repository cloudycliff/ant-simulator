# 开发计划（Roadmap）

## 1. 项目目标

用 Three.js 做一个 Web 版蚂蚁生态模拟器：参考真实蚂蚁的生态与社会分工，尽量还原蚁穴构造和蚁穴周围的觅食环境。蚂蚁有自己的社会分工并自主行动；玩家可以在场景中自由移动观察，点选蚁穴区域、蚂蚁个体查看信息。

## 2. 已确认的需求（2026-10-21 与需求方确认）

| 项目 | 决定 |
|---|---|
| 物种原型 | 黑毛蚁 *Lasius niger*（无兵蚁，防御由工蚁承担） |
| 美术风格 | 风格化低多边形，全部程序生成，不依赖外部素材 |
| 蚁穴呈现 | 真 3D 地下隧道网络，土壤半透明/剖切，相机可以飞进去 |
| 蚁穴生成 | 开局程序化生成，之后按人口增长扩建新房间 |
| 蚂蚁规模 | 1000–3000 只 |
| 玩家角色 | 自由观察 + 轻度干预（投放食物、放置障碍、引入天敌、浇水） |
| 生态要素 | 昼夜循环、蚜虫放牧（蜜露）、天敌（蜘蛛、蚁狮）、天气（下雨冲刷信息素、入口进水） |
| 交付节奏 | 先做可玩原型验收，再分阶段迭代 |

**明确不做**（架构上留位置，以后可加）：敌对蚁群与领地战争、季节变化与婚飞。

每条决定的背景和取舍见 [DECISIONS.md](DECISIONS.md)。

## 3. 阶段划分

### 第一阶段：可玩原型 ✅ 已完成（2026-10-21）

- [x] 工程框架（Vite + TypeScript + Three.js）
- [x] 程序化地形、草丛、石块、落叶、枯枝、草本植物
- [x] 3D 蚁穴：两个入口与火山口状土丘、主竖井、10 个房间、3 条挖掘中的盲端隧道
- [x] 土壤分层剖面与地下透视模式（相机入地自动开启）
- [x] 约 1000 只蚂蚁的实例化渲染，着色器驱动三脚架步态
- [x] 四类分工：蚁后、保育蚁、内务蚁、觅食蚁（含侦察蚁）
- [x] 信息素觅食（路径整合返巢 + 路径信息素招募 + 地点记忆）
- [x] 基础昼夜循环（日月光照、天空、星空、土壤温湿度模型）
- [x] 点选查看蚂蚁、房间、食物源、入口、垃圾堆、石块、植物
- [x] 自由飞行相机、跟随单只蚂蚁、平滑飞向目标
- [x] 时间控制（暂停、1/2/5/10/20 倍速）
- [x] 额外完成：卵→幼虫→蛹→成虫的完整发育周期、尸体搬运、垃圾清理、食物变质、信息素热力图、按分工着色

### 第二阶段：生态深化 ✅ 已完成（2026-10-21）

- [x] **按日龄分工**（年龄多型性）：工蚁按“行为年龄”排序，从保育→内务→觅食转换；按幼体数量和储备天数动态计算各职别需求，觅食蚁不足时较年轻的工蚁提前出巢，缺口明显时也会逆向转换
- [x] 交哺与“社会胃”：甜液只存在工蚁嗉囊里，饥饿的蚂蚁向同伴乞食，归巢的觅食蚁把蜜露分给巢内工蚁
- [x] 蚂蚁之间的接触与触角交流（空间哈希）；满载归来的觅食蚁通过接触激发巢内同伴出巢
- [x] 蚜虫放牧：4 株寄主植物 + 2 处附近植物上的蚜虫群，被照料时增殖更快；觅食蚁爬上茎秆采集蜜露、驱赶天敌，并对固定的蚜虫群保持忠诚
- [x] 按温度搬运幼体：大石块下新增浅层“向阳育幼室”，白天升温后保育蚁把蛹搬上来，傍晚搬回深层蛹室
- [x] 蚁穴扩建：拥挤时规划新房间，内务蚁先挖隧道（隧道几何真实延长）再挖房间（房间从门口逐渐“长”出来）
- [x] 统计面板（`T`）：各职别人口曲线、储食室与社会胃曲线
- [x] 信息素热力图细化：新增蓝色“领地足迹”通道，路径信息素按浓度从橙红到亮黄，并配图例
- 额外完成：植物 / 蚜虫群信息面板、房间扩建进度、`?skip=` 快进与 `?view=` 开关参数

### 第三阶段：天敌、天气、干预与打磨（已完成，待验收）

按以下顺序进行，每完成一项提交一次：

- [x] 玩家干预工具：投放食物（含糖水）、放置障碍（小石子 / 大石块 / 树枝路障，可移除）、浇水（水洼冲刷信息素、蒸发收缩）
- [x] 存档：保存在浏览器本地，每分钟和关闭页面时自动保存，打开页面时接着上次继续；可手动保存、读取上次存档、重新开始
- [x] 天敌：狼蛛（地表游猎，捕食后离开）、蚁狮（漏斗陷阱），取代原来的“地表意外死亡”；干预工具加入“放入 / 赶走天敌”
- [x] 警报信息素与工蚁防御：受攻击处释放警报，附近工蚁赶来围攻狼蛛；巢口受威胁时觅食蚁留巢、内务蚁出巢警戒；爬出过陷阱的蚂蚁绕开它；发觉走近的狼蛛提前躲开
- [x] 天气：下雨冲刷信息素、积水洼，觅食蚁躲雨，内务蚁雨前封堵入口、雨后清开，没封好时浅层房间进水
- [x] 性能优化到 3000 只（地形与温度缓存、远处简化网格、帧预算；评估后不需要 Web Worker，见 DECISIONS T-031）
- [x] 打磨：蚂蚁碰撞避让、地表热闹度、扩大已有房间、随机地图、下雨体验、蚁狮坑与雨中画面、房间门口拥挤

## 4. 工作量与资源预估（立项时）

| 阶段 | 新增代码 | Agent 工作时长 |
|---|---|---|
| 第一阶段：原型 | ~4.5k 行 | 4–6 小时 |
| 第二阶段：生态深化 | ~3k 行 | 5–9 小时 |
| 第三阶段：天敌、天气、干预 | ~3k 行 | 6–10 小时 |
| **合计** | **约 1–1.1 万行** | **15–25 小时** |

- 换算为人工开发约 30–45 人天
- Token 预估：第一阶段输出 20–30 万、总处理 600–1000 万；三个阶段合计输出 60–90 万、总处理 3000–5000 万（大部分命中缓存）
- 最大的不确定因素：行为调参和视觉修改的轮数

各阶段的实际用量记录在 [PROGRESS.md](PROGRESS.md)。
