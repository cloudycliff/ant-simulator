# 开发计划（赛博养蜂）

## 1. 项目目标

在花园里的一个玻璃观察箱中模拟一窝中华蜜蜂：蜂王产卵、幼虫发育、工蜂按日龄换工作、采集蜂外出采花回来跳舞招募同伴、花蜜酿成蜂蜜封盖。玩家贴着玻璃看巢脾上的每一个巢房，或者跟着一只蜂飞到花丛再飞回来，偶尔种花、放糖水。

## 2. 已确认的需求（2026-10-26 与需求方确认）

| 项目 | 决定 |
|---|---|
| 原型 | 中华蜜蜂 *Apis cerana*，查不到的习性参考西方蜜蜂（P-001） |
| 美术风格 | 风格化低多边形，全部程序生成（P-002） |
| 视角 | 花园里的观察箱，两框巢脾竖着摞，和花园是连续的一个场景（P-003） |
| 规模 | 2000～3000 只（P-004） |
| 玩家角色 | 观察 + 轻度干预；第一阶段只有种花、放糖水（P-005） |
| 季节 | 第一阶段固定在夏天（P-006） |
| 筑巢 | 第一阶段就做巢脾向外长（P-007） |
| 名字 | 赛博养蜂（P-008） |
| 时间、空间尺度 | 1 天 = 600 秒，发育压缩到约 1/3；巢里真实大小，巢外压缩距离（T-002、T-003） |
| 交付节奏 | 先做可玩原型验收，再分阶段迭代 |

**第一阶段不做**：温度调节、天气、胡蜂和其他威胁、飞逃、分蜂和换王、季节、取蜜和加框、添加到主屏幕。

每条决定的背景和取舍见 [DECISIONS.md](DECISIONS.md)。

## 3. 阶段划分

### 第一阶段：可玩原型

**准备**
- [x] 整理中蜂的数值：卵、幼虫、蛹的天数（工蜂、雄蜂、蜂王），巢房尺寸，日龄分工的时间点，摇摆舞的距离编码，扇风朝向，雄蜂房封盖（见 BALANCE.md）
- [ ] 联网核对 BALANCE.md 里标着“教材”的数值
- [x] 一次性原型，验证没把握的部分：巢脾的渲染和点选（约 1～2 万个巢房）、巢脾表面上爬行、三维飞行的手感（结论见 DECISIONS T-005 到 T-009、P-009）

**工程**
- [x] 照鱼缸的结构建出 `src/games/bee`、`bee.html`、`src/bee.ts`
- [x] `vite.config.ts` 改成按 mode 查表；`package.json` 的构建加上蜜蜂
- [x] `scripts/check.mjs` 加上蜜蜂的构建和无界面测试；`scripts/i18ncheck.ts` 加上蜜蜂的词典
- [x] `AGENTS.md` 改成通用的写法或分游戏列出路径
- [x] 框架里按蚂蚁调死的数值改成由游戏传入，蚂蚁基线不变：`Environment` 的雾、天空半径、阴影范围；跟随的平滑系数；镜头移动速度（T-009，框架 DECISIONS T-073）

**世界**
- [x] 花园：地面、草、花丛（几种花，按一天中的时刻开放、流蜜，采过后慢慢恢复）
- [x] 观察箱：木架、顶棚、玻璃、两框的框条、巢门管
- [x] 巢脾：两面的六边形网格，巢房状态有空、卵、幼虫、封盖子、花蜜、蜂蜜（封盖或未封盖）、花粉；开局只造了一部分

**蜜蜂**
- [x] 蜂王：在巢脾上巡游，找空巢房产卵
- [x] 发育：卵 → 幼虫（要哺育蜂喂）→ 封盖 → 羽化；工蜂和少量雄蜂
- [x] 日龄分工：清理巢房 → 哺育 → 筑巢、接收和酿造花蜜 → 守卫 → 采集，按需要调整（T-015）。守卫只是站在巢门口，赶走别的虫子要等第二阶段的威胁
- [x] 运动：巢里在巢脾表面爬（两面之间绕过框边），巢外三维飞行，进出巢门（T-013）。雄蜂还不出巢
- [x] 采集：侦察蜂找花 → 回巢跳摇摆舞（近处是圆舞），角度按太阳方位 → 被招募的蜂飞去那片花 → 采蜜、采粉 → 回巢把花蜜交给内勤蜂 → 放进巢房、扇风浓缩 → 封盖（T-013、T-014）
- [x] 吃：成蜂和幼虫消耗蜂蜜和花粉；储蜜靠负反馈稳定，不单向漂移（T-014 的缺粉程度、T-015 的缺蜜程度）

**界面**
- [x] 点选、信息面板、跟随：蜂、巢房、花丛
- [x] 视图开关：分工着色、巢房内容着色、摇摆舞标记、淡化蜂（P-009）（T-017）
- [x] 统计：只数、分工、储蜜和储粉、子脾数量
- [x] 工具：种花、放糖水（T-016）
- [x] 蜂身的动作：爬的时候六条腿按三脚架步态迈、触角动，飞的时候翅膀扇，落在花上收拢，扇风酿蜜时停着扇（照蚂蚁 T-009 在顶点着色器里摆）
- [x] 远处的蜂放大到至少 5 px（T-007）；蜂身三级细节和视锥剔除（T-006）。放大只给飞着的蜂（巢里的蜂放大后从远处看整箱是一团褐色）

**收尾**
- [x] 存档和读档往返一致（巢脾、花丛、巢里和在外面的蜂、跳舞、跟舞读出的地方、交接）
- [x] 无界面测试（照 `scripts/games/aquarium/aquatest.ts`），加进 `npm run check`
- [ ] 截图：桌面和竖屏手机，白天、夜里、选中、跟随、工具、英文
- [ ] 部署到 `cyberant.pages.dev/bee.html`

**验收标准**：
- 无界面跑 10 个游戏日：只数稳定或缓慢增长，储蜜在白天增加、夜里回落但不单向漂移，日龄分工的几种工作都有蜂在做
- 跳舞招募有效：被某支舞招募的蜂大多飞到舞里指的那片花
- 巢脾边缘长出新的巢房
- 画面上能贴着玻璃看清卵、幼虫、封盖、蜂蜜，能跟一只采集蜂走完一趟

### 第二阶段：巢里的环境和威胁

- [ ] 温度：育儿区维持约 35°C，热了扇风、冷了振翅产热
- [ ] 天气：下雨不出巢
- [ ] 胡蜂：在巢门口捕蜂；中蜂成片抖动翅膀吓退、围成热球闷死
- [ ] 巢虫、中囊病
- [ ] 飞逃：受扰过度、缺食、病虫害严重时整群弃巢
- [ ] 玩家工具：取蜜、加框、对付胡蜂

- [ ] 分蜂、造王台、换王

## 4. 风险与应对

| 风险 | 应对 |
|---|---|
| 1～2 万个巢房加 3000 只蜂的渲染开销 | 原型已验证：巢脾远处着色器平板、近处实例网格（T-005），蜂身三级细节加剔除（T-006）。手机上的帧率还没测 |
| 三维飞行是框架没有的运动方式 | 先写在游戏里；只有蜜蜂一个游戏用，不提进 `core` |
| 摇摆舞看不出来、招募效果不明显 | 舞的路线画成可开关的标记；无界面测试统计招募到对的花丛的比例 |
| 中蜂的资料少 | 查不到的按西方蜜蜂，在 BALANCE.md 里注明来源 |
| 花园 40 m 见方，从高处看不见蜂 | 远处的蜂放大到至少 5 px（T-007） |
| 巢里真实大小，巢房小，点选难 | 巢房用射线和巢面平面求交换算编号，蜂按屏幕距离点选，贴近巢脾时容差收小 |
| 蜂多了盖住巢房 | 淡化蜂的视图（P-009） |
